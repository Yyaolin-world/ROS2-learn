# 2-4 工作空间（Workspace）

## 1. 什么是工作空间

工作空间是一个**存放功能包的目录**，也是 ROS 2 编译和运行的基本单位。

- 一个工作空间里可以放多个功能包
- 功能包不能独立编译，必须在工作空间里编译
- 工作空间是环境变量的边界 —— `source` 它的 `setup.bash`，里面的包才对外可见

## 2. 标准结构

```
chap2_ws/                      ← 工作空间根目录
├── src/                       ← 唯一需要自己维护的目录
│   ├── demo_cpp_pkg/          ← 功能包
│   └── demo_python_pkg/       ← 功能包
├── build/                     ← 编译中间文件（自动生成）
├── install/                   ← 编译产物（自动生成）
└── log/                       ← 编译日志（自动生成）
```

| 目录 | 内容 | 要不要管 |
|------|------|---------|
| `src/` | 功能包源码 | **要**，所有手写的代码都在这 |
| `build/` | 编译中间文件 | 不管，可删 |
| `install/` | 编译产物、`setup.bash` | 不管，可删 |
| `log/` | 每次编译的日志 | 不管，可删，出错了来这看 |

**关键**：`src` 用来放源码，`build/install/log` 是编译时自动生成的，后三个删掉重新 `colcon build` 就能恢复，所以通常写进 `.gitignore`。

## 3. 创建流程

**注意**：`ros2 pkg create` 只会生成一个**空壳**（`package.xml` + `CMakeLists.txt` / `setup.py`），里面**没有源码，也没有注册任何可执行文件**。直接 `colcon build` 能通过，但 `ros2 run` 会报「找不到可执行文件」。所以必须自己补上「写代码」和「注册可执行文件」两步。

```bash
# 1. 建工作空间和 src 目录
mkdir -p chap2_ws/src
cd chap2_ws/src

# 2. 在 src 里建功能包（只是空壳）
ros2 pkg create demo_cpp_pkg --build-type ament_cmake --dependencies rclcpp
ros2 pkg create demo_python_pkg --build-type ament_python --dependencies rclpy
```

### C++ 包：写代码 + 改 CMakeLists.txt

新建 `demo_cpp_pkg/src/cpp_node.cpp`：

```cpp
#include "rclcpp/rclcpp.hpp"

int main(int argc, char **argv)
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<rclcpp::Node>("cpp_node");
    RCLCPP_INFO(node->get_logger(), "hello cpp_node");
    rclcpp::spin(node);
    rclcpp::shutdown();
    return 0;
}
```

再在 `demo_cpp_pkg/CMakeLists.txt` 里（`find_package(rclcpp REQUIRED)` 之后）加上下面几行，把源码编译成名为 `cpp_node` 的可执行文件并安装：

```cmake
add_executable(cpp_node src/cpp_node.cpp)
ament_target_dependencies(cpp_node rclcpp)   # 等价写法：target_link_libraries(cpp_node rclcpp::rclcpp)
install(TARGETS cpp_node
  DESTINATION lib/${PROJECT_NAME})
```

> 生成空壳时，`--dependencies rclcpp` 只帮你写了 `find_package(rclcpp REQUIRED)` 和 `package.xml` 里的 `<depend>rclcpp</depend>`，**`add_executable` 这一坨不会帮你写**，必须手动加。

### Python 包：写代码 + 改 setup.py

新建 `demo_python_pkg/demo_python_pkg/python_node.py`：

```python
import rclpy
from rclpy.node import Node

def main():
    rclpy.init()
    node = Node("python_node")
    node.get_logger().info("你好 python 节点")
    rclpy.spin(node)
    rclpy.shutdown()
```

再在 `demo_python_pkg/setup.py` 里加 `entry_points`，把 `python_node` 这个名字和 `main` 函数绑定（否则 `ros2 run` 找不到）：

```python
entry_points={
    'console_scripts': [
        'python_node = demo_python_pkg.python_node:main',
    ],
},
```

### 编译、加载、运行

```bash
# 3. 回到工作空间根目录编译（关键！）
cd ..
colcon build --symlink-install

# 4. 加载环境变量
source install/setup.bash

# 5. 运行
ros2 run demo_cpp_pkg cpp_node
ros2 run demo_python_pkg python_node
```

## 4. 核心规则

1. **`colcon build` 必须在工作空间根目录执行**，也就是 `src` 的上一层。在 `src` 里执行的话，`build/install/log` 会长在 `src` 里面，结构就乱了。
2. **`src` 里只放功能包**，不要放 `build/install/log`，也不要在 `src` 里再套一层工作空间。
3. **每次新开终端都要重新 `source`**，环境变量不会跨终端保留。
4. **先 source 底层，再 source 自己**（顺序不能反）：
   ```bash
   source /opt/ros/lyrical/setup.bash              # underlay：ROS 2 本体
   source ~/ROS2/chap2/chap2_ws/install/setup.bash # overlay：自己的工作空间
   ```
5. **改了 C++ 代码要重新 `colcon build`**；改了 Python 代码如果用 `--symlink-install` 编译则不用（见下）。

## 5. 常用 colcon 命令

```bash
colcon build                          # 编译工作空间里的所有包
colcon build --packages-select demo_cpp_pkg   # 只编译指定包（包多了能省很多时间）
colcon build --symlink-install        # 用软链接代替拷贝（Python 包强烈建议）
rm -rf build install log && colcon build      # 彻底重新编译
```

**`--symlink-install` 对 Python 包很重要**：

不加这个参数时，`python_node.py` 会被**拷贝**一份到 `install/` 里，所以你改了源码必须重新 `colcon build` 才生效。

加了之后，colcon 不再拷贝，而是搭一条**指回源码的链**：

```
install/demo_python_pkg/lib/python3.14/site-packages/demo-python-pkg.egg-link
        │  内容：指向 build/demo_python_pkg
        ↓
build/demo_python_pkg/demo_python_pkg   ──软链接──→   src/demo_python_pkg/demo_python_pkg
```

Python 导入时顺着这条链走回 `src/`，所以**改完 `.py` 直接跑就生效**，不用重编。

```bash
colcon build --symlink-install
```

C++ 包也会受影响：`install/demo_cpp_pkg/lib/demo_cpp_pkg/cpp_node` 是指向 `build/demo_cpp_pkg/cpp_node` 的软链接。但二进制终归要重新编译，改了 `.cpp` 还是一样得 `colcon build`。

## 6. overlay（叠加）机制

ROS 2 的环境是**层层叠加**的：

```
你自己的工作空间   ← overlay（上层，优先）
        ↑ 叠加在
/opt/ros/lyrical   ← underlay（底层，ROS 2 本体）
```

- 先 `source` 的下层，后 `source` 的上层，上层覆盖下层
- 所以如果你自己的包里有一个和系统同名的包，会优先用你自己的 —— 这就是能用自己版本覆盖系统包的原因
- 查当前环境能找到哪些包：`ros2 pkg list`

## 7. 坑：`colcon build` 跑错目录

**现象**：`build/`、`install/`、`log/` 出现在了 `src/` 里面：

```
chap2_ws/
└── src/
    ├── demo_cpp_pkg/
    ├── demo_python_pkg/
    ├── build/          ← 长错地方了
    ├── install/        ← 长错地方了
    └── log/            ← 长错地方了
```

**原因**：执行 `colcon build` 时人在 `src/` 目录里，colcon 就把 `src/` 当成了工作空间根目录。
典型现场：`~/ROS2/chap2/chap2_ws/src$ colcon build`

**后果**：编译能过、程序能跑，但结构不符合规范，`source` 路径变成 `chap2_ws/src/install/setup.bash`；后面加包、做 overlay 时会越来越乱。

**修复**：把生成物挪到上一层，重新编译。

```bash
cd chap2_ws
rm -rf src/build src/install src/log
colcon build --symlink-install
source install/setup.bash
```

**正确姿势**：`cd` 到工作空间根目录再 `colcon build`，看提示符里 `src` 的上一层对不对。

## 8. 坑：建了包却跑不起来

**现象**：`colcon build` 一路通过，但 `ros2 run demo_cpp_pkg cpp_node` 报 `No executable found`。

**原因**：`ros2 pkg create` 只生成空壳，不生成源码，也不注册可执行文件。三样东西缺一不可：

| 缺什么 | 症状 |
|--------|------|
| 没写 `.cpp` / `.py` 源码 | 没有东西可编译 / 没有东西可运行 |
| C++ 包没改 `CMakeLists.txt`（缺 `add_executable` + `install`） | 编译不出可执行文件，`install/` 里是空的 |
| Python 包没改 `setup.py`（缺 `entry_points`） | 装了包，但 ROS 2 不知道 `python_node` 这个命令指向哪个函数 |

**排查**：先看 `install/demo_cpp_pkg/lib/demo_cpp_pkg/` 里有没有 `cpp_node`，再看 `CMakeLists.txt` 里有没有 `add_executable`；Python 包直接看 `setup.py` 的 `entry_points`。

## 9. 记忆要点

- 工作空间 = `src` + `build` + `install` + `log`，只有 `src` 要自己维护
- `ros2 pkg create` 只生成空壳，**源码要自己写，可执行文件要自己注册**
- C++ 包注册在 `CMakeLists.txt`（`add_executable` + `install`），Python 包注册在 `setup.py`（`entry_points`）
- `colcon build` 在**工作空间根目录**跑，不在 `src` 里跑
- `source install/setup.bash` 之后，里面的包才能被 `ros2 run` 找到
- 新开终端 → 重新 source
- Python 包用 `--symlink-install` 编译，改代码不用重编
