# 2-2～2-3 用功能包组织节点（C++）

本机环境：**ROS 2 Jazzy**（`/opt/ros/jazzy`）。

## 1. 完整流程（每一步在哪个目录执行）

| 步骤 | 命令 | 在哪执行 |
|------|------|----------|
| 1. 建工作空间 | `mkdir -p xx_ws/src` | 任意目录（建议 `~/ROS2`） |
| 2. 建功能包 | `ros2 pkg create 包名 --build-type ament_cmake --dependencies rclcpp` | `xx_ws/src` |
| 3. 写源码 | 新建 `xx_ws/src/包名/src/xxx.cpp` | — |
| 4. 改 `CMakeLists.txt` | 加 `add_executable` / 链接依赖 / `install` | `xx_ws/src/包名`（包根目录） |
| 5. 编译 | `colcon build` | **`xx_ws` 根目录** |
| 6. 加载环境 | `source install/setup.bash` | **`xx_ws` 根目录**（相对路径） |
| 7. 运行 | `ros2 run 包名 可执行名` | 任意目录（同一终端已 source 即可） |

对应命令：

```bash
# 1) 工作空间
mkdir -p xx_ws/src

# 2) 功能包（只是空壳）
cd xx_ws/src
ros2 pkg create demo_cpp_pkg --build-type ament_cmake --dependencies rclcpp

# 3) 写源码：xx_ws/src/demo_cpp_pkg/src/cpp_node.cpp

# 4) 改 CMakeLists.txt（见下）

# 5) 回工作空间根目录编译
cd xx_ws
colcon build
# 编译后自动出现 build/  install/  log/

# 6) 加载环境（相对路径，必须当前在 xx_ws 里）
source install/setup.bash

# 7) 运行（在哪个目录都行）
ros2 run demo_cpp_pkg cpp_node
```

## 2. 每一步的要点

### 1）工作空间

工作空间就是一层外壳，`src` 是唯一需要自己维护的目录：

```
xx_ws/
├── src/          ← 放功能包，自己维护
├── build/        ← 编译中间文件（colcon build 生成）
├── install/      ← 编译产物 + setup.bash（colcon build 生成）
└── log/          ← 编译日志（colcon build 生成）
```

- `build/install/log` 是 **`colcon build` 之后**出现的，不是运行节点后出现的，删掉重编即可恢复。
- `xx_ws` 这个名字只是习惯，不是语法要求。

### 2）功能包

`ros2 pkg create` 只生成空壳（`package.xml`、`CMakeLists.txt`、空的 `src/` 和 `include/`），**不写源码，也不注册可执行文件**。所以后面两步（写代码、改 CMakeLists）不能省。

### 3）源码位置

注意有**两个 `src`**，层级不同：

```
xx_ws/src/                  ← ① 工作空间的 src，放“功能包”
└── demo_cpp_pkg/
    ├── src/                ← ② 功能包的 src，放 .cpp 源码
    ├── include/            ← 头文件（.hpp）
    ├── CMakeLists.txt
    └── package.xml
```

代码：

```cpp
#include "rclcpp/rclcpp.hpp"

int main(int argc, char **argv)
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<rclcpp::Node>("cpp_node");
    RCLCPP_INFO(node->get_logger(), "hello cpp_node");
    rclcpp::spin(node);
    rclcpp::shutdown();
    return 0;
}
```

### 4）CMakeLists.txt（包根目录）

在 `find_package(rclcpp REQUIRED)` 之后加三块，缺一不可：

```cmake
add_executable(cpp_node src/cpp_node.cpp)              # ① 源码 → 可执行文件
target_link_libraries(cpp_node PUBLIC rclcpp::rclcpp)  # ② 链接依赖
install(TARGETS cpp_node
  DESTINATION lib/${PROJECT_NAME})                     # ③ 安装到 ROS 约定的位置
```

- ① 的第一个参数是可执行文件名（`ros2 run` 用它），和包名无关，可以随便起。
- ② 用的是 CMake 原生写法；旧写法 `ament_target_dependencies(cpp_node rclcpp)` 在 Jazzy 上**仍然可用**。
- ③ 的 `lib/${PROJECT_NAME}` 是 ROS 2 约定，照着写，别改。

### 5）编译

```bash
cd xx_ws          # src 的上一层
colcon build
```

必须在**工作空间根目录**执行。在 `src/` 里执行的话，`build/install/log` 会长进 `src/` 里，结构就乱了。

如果配置了 conda 且 `python3` 指向 conda（3.14），纯 C++ 包通常没事；一旦包含消息生成（`rosidl_generate_interfaces`）会报 `No module named 'em'`，此时用：

```bash
colcon build --cmake-args -DPython3_EXECUTABLE=/usr/bin/python3
# 或者先 conda deactivate
```

### 6）source

```bash
source install/setup.bash
```

- 这里写的是**相对路径**，所以必须在 `xx_ws` 根目录执行；在别的目录就换成绝对路径：
  `source ~/ROS2/chap3/topic_ws/install/setup.bash`
- **每次新开终端都要 source 一次**，环境变量不跨终端保留。
- 前提是底层 ROS 已加载（一般 `~/.bashrc` 已 source `/opt/ros/jazzy/setup.bash`）。确认：`echo $ROS_DISTRO` 输出 `jazzy`。
- 顺序：先 underlay（`/opt/ros/jazzy`），再 overlay（自己的 `xx_ws`）。

### 7）运行

```bash
ros2 run demo_cpp_pkg cpp_node
# [INFO] [...] [cpp_node]: hello cpp_node
```

- `ros2 run` 在**任何目录**都能执行，只要这个终端 source 过对应工作空间。
- 它是按路径找可执行文件的：

```
install/demo_cpp_pkg/lib/demo_cpp_pkg/cpp_node
        └── 包名 ──┘     └── 包名 ──┘   └─ add_executable 的名字 ─┘
```

所以：

- 包名必须和 `DESTINATION lib/${PROJECT_NAME}` 对得上；
- 可执行名必须和 `add_executable` 的第一参数对得上；
- 两个名字可以不同，例如改成 `add_executable(my_node ...)`，运行就是 `ros2 run demo_cpp_pkg my_node`。

## 3. 常用自查

```bash
ros2 pkg executables demo_cpp_pkg   # 包注册了哪些可执行文件
ros2 pkg prefix demo_cpp_pkg        # 包安装到哪
```

- `colcon build` 通过但 `ros2 run` 报找不到：先看 `install/<包名>/lib/<包名>/` 里有没有可执行文件，再看 CMakeLists 的三块是否齐全。
- 改 `.cpp` 要重新 `colcon build`；改 launch / 参数文件一般不用。

## 4. 教材（Humble）与本机（Jazzy）的差异

| 场景 | 教材写法 | 本机可用写法 |
|------|----------|--------------|
| CMake 链接依赖 | `ament_target_dependencies(目标 rclcpp)` | `target_link_libraries(目标 PUBLIC rclcpp::rclcpp)`，旧写法也仍可用 |
| 消息包依赖 | `ament_target_dependencies(目标 std_msgs)` | `target_link_libraries(目标 PUBLIC ${std_msgs_TARGETS})`（需先 `find_package(std_msgs REQUIRED)`） |

> 更正：之前笔记里写“本机是 Lyrical、`ament_target_dependencies` 已被移除”是错的。本机实际是 **Jazzy**，该宏由 `ros-jazzy-ament-cmake-target-dependencies` 提供，仍然存在。若真遇到 `Unknown CMake command "ament_target_dependencies"`，先检查 CMakeLists 里是否有 `find_package(ament_cmake REQUIRED)`，以及编译时是否正确 source 了 `/opt/ros/jazzy/setup.bash`。

**转换规则：**

- 普通库 → `包名::包名`，如 `rclcpp::rclcpp`
- 消息包 → `${包名_TARGETS}`，如 `${std_msgs_TARGETS}`

> 策略：不提前啃迁移文档，遇到报错再查，查完往表格里加一行。
