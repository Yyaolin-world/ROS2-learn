# ROS2 学习笔记

## 1. C++ 使用功能包创建节点

**命令：**

```bash
ros2 pkg create demo_cpp_pkg --build-type ament_cmake --dependencies rclcpp
```

**解释：**

| 部分 | 含义 |
|------|------|
| `ros2 pkg create` | 调用 ROS2 的功能包创建工具 |
| `demo_cpp_pkg` | 要创建的功能包名称（可自定义） |
| `--build-type ament_cmake` | 指定构建类型为 C++（CMake） |
| `--dependencies rclcpp` | 声明依赖 `rclcpp`（C++ 客户端库，提供节点功能） |

- 执行后会在当前目录生成一个 `demo_cpp_pkg` 文件夹，包含 `CMakeLists.txt`、`package.xml`、`src/`、`include/` 等标准结构。
- `rclcpp` 是 ROS2 的 C++ 客户端库，创建节点所需的 `rclcpp::Node` 就来自它。

## 2. 坑：`ament_target_dependencies` 找不到

**现象：**

```
CMake Error at CMakeLists.txt:14 (ament_target_dependencies):
  Unknown CMake command "ament_target_dependencies".
```

**原因：**

`ament_target_dependencies` 不是 CMake 原生命令，而是 ament 提供的一个宏。它在 **Kilted（2025.05）被标记弃用，在 Lyrical（2026.05）被彻底移除**。所以本机的 `/opt/ros/lyrical/share/` 里已经搜不到这个宏了，CMake 自然报"未知命令"。

教材用的是 Humble 时代的写法，所以会踩这个坑。

**解决：**

用 CMake 原生的 `target_link_libraries`，直接链接 `rclcpp` 导出的 imported target：

```cmake
add_executable(cpp_node ./src/cpp_node.cpp)
target_link_libraries(cpp_node PUBLIC rclcpp::rclcpp)   # 替代 ament_target_dependencies
```

`find_package(rclcpp REQUIRED)` 会加载 `rclcppExport.cmake`，里面定义了 `rclcpp::rclcpp`。用它链接，头文件路径、库文件、编译选项都会自动传递到目标上。

**验证：**

```bash
$ colcon build
Finished <<< demo_cpp_pkg [2.78s]
Summary: 1 package finished

$ ros2 run demo_cpp_pkg cpp_node
[INFO] [1790911847.677748810] [cpp_node]: hello cpp_node
```

## 3. 对照表：教材（Humble）→ 本机（Lyrical）

本机环境：**Ubuntu 26.04 + ROS 2 Lyrical Luth（LTS，支持到 2031.05）**。
教材基于 Humble（Ubuntu 22.04），中间隔了 Iron / Jazzy / Kilted 四个版本。

核心概念（节点、话题、服务、参数、Action、launch、tf2、URDF）基本没变，差别主要集中在**构建配置**和**部分功能包的 API**。遇到一条记一条：

| 场景 | 教材写法（Humble） | 本机写法（Lyrical） | 备注 |
|------|-------------------|---------------------|------|
| CMake 链接依赖 | `ament_target_dependencies(cpp_node rclcpp)` | `target_link_libraries(cpp_node PUBLIC rclcpp::rclcpp)` | 见第 2 条 |

**通用转换规则：**

- **普通库**（如 `rclcpp`）→ 写 `包名::包名`，例如 `rclcpp::rclcpp`
- **消息包**（如 `std_msgs`）→ 写 `${包名_TARGETS}`，例如 `${std_msgs_TARGETS}`

**已知有变动、但还没学到/没遇到（待验证）：**

- `control_toolbox` 的 PID：部分参数和构造函数有改动
- Gazebo 仿真：变动较大
- Nav2：有较大重构

## 4. 本节小结：从建包到运行节点的完整流程

**1）创建工作空间并建包**

```bash
mkdir -p chap2-2_cpp/src && cd chap2-2_cpp/src
ros2 pkg create demo_cpp_pkg --build-type ament_cmake --dependencies rclcpp
```

**2）写节点代码** `demo_cpp_pkg/src/cpp_node.cpp`

```cpp
#include "rclcpp/rclcpp.hpp"

int main(int argc, char **argv)
{
    rclcpp::init(argc, argv);
    auto node = std::make_shared<rclcpp::Node>("cpp_node");
    RCLCPP_INFO(node->get_logger(), "hello cpp_node");
    rclcpp::spin(node);
    rclcpp::shutdown();
    return 0;
}
```

**3）配置 `CMakeLists.txt`**（关键三行）

```cmake
find_package(rclcpp REQUIRED)
add_executable(cpp_node ./src/cpp_node.cpp)
target_link_libraries(cpp_node PUBLIC rclcpp::rclcpp)
install(TARGETS cpp_node DESTINATION lib/${PROJECT_NAME})
```

**4）编译**（在工作空间根目录，即 `src` 的上一层）

```bash
colcon build
```

**5）加载环境变量**（每次新开终端都要做一次）

```bash
source install/setup.bash
```

**6）运行**

```bash
ros2 run demo_cpp_pkg cpp_node
# [INFO] [1790912613.219733688] [cpp_node]: hello cpp_node
```

**记忆要点：**

- `ros2 run 包名 可执行文件名` 实际查找的路径是：
  `install/<包名>/lib/<包名>/<可执行名>`
  ```
  install/demo_cpp_pkg/lib/demo_cpp_pkg/cpp_node
          └── ① ──┘     └── ② ──┘   └── ③ ──┘
  ```
  - ① 来自 `project(demo_cpp_pkg)`，即包的 install 前缀（`ros2 pkg prefix` 返回它）
  - ② 来自 `DESTINATION lib/${PROJECT_NAME}`，ROS 2 约定，照着写别改
  - ③ 来自 `add_executable(cpp_node ...)`，**和包名无关，可以随便起**

- 所以两个名字可以不一样：把 `add_executable(cpp_node ...)` 改成 `my_node`，运行命令就变成 `ros2 run demo_cpp_pkg my_node`
- 但包名必须和 `DESTINATION lib/${PROJECT_NAME}` 对得上，否则 `ros2 run` 找不到
- 验证用的两个命令：`ros2 pkg prefix demo_cpp_pkg`、`ros2 pkg executables demo_cpp_pkg`
- 改了代码要重新 `colcon build`，改了 launch/参数文件一般不用
- 编译只在工作空间根目录做，别在 `src/` 里做
